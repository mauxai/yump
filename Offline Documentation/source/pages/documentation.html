6amStudio Documentation

6amStudio is a self-hosted, AI-powered image editing platform. Users upload images and transform them with natural-language prompts, one-click effects, and reusable templates — powered by Google Gemini and OpenAI image models. A credit-based billing system, a full admin panel, and a documented REST API are built in.

Introduction

The product ships as a single Next.js 14 application backed by a MySQL database. One process serves three surfaces:

SurfaceURLAudience
User App / End users — dashboard, AI editor, projects, gallery, billing, notifications, settings
Admin Panel /admin Operators — user management, plans, AI models, content libraries, integrations, audit log
REST API /api/v1 Developers — JWT-authenticated API with an OpenAPI specification

Installation is handled by a built-in web install wizard: until setup completes, every request is redirected to /install, where the buyer connects a database, activates the purchase code, and creates the super admin account — no manual database imports or config-file editing required.

System Features

AI Editor

  • Prompt-based editing — describe a change in natural language and the selected AI model renders it.
  • Multiple AI models — Google Gemini and OpenAI image models run side by side; each model is added from the admin panel with its own API key and per-use credit cost, and one model is marked as the default.
  • Effect presets — one-click, admin-curated effects grouped by color-coded categories, each backed by a prompt template.
  • Templates — a gallery of pre-built scene templates with preview images; usage of each template is tracked.
  • Suggested prompts — quick-start prompt chips, editable from the admin panel.
  • Edit history tree — every generation is stored as a node with its parent, so users can branch and step back through versions.
  • Sketch overlay — draw on the canvas to guide the model, with a configurable brush color.
  • Credit awareness — the editor displays the user's remaining credits and the cost of the selected model before generating.

User App

  • Authentication — email/password registration and login, optional Google sign-in, and a forgot-password flow with an emailed one-time code.
  • Dashboard — recent projects and credit balance at a glance.
  • Projects — create projects from uploaded images; browse, search, and manage them.
  • Gallery — all generated images across projects in one filterable view.
  • History & activity — a searchable timeline of edits, project creations, and purchases.
  • Billing — credit plans, gateway checkout (Stripe built in), and a filterable transaction history.
  • Notifications — an in-app notification center, with optional Firebase Cloud Messaging push notifications.
  • Settings — profile, avatar, password, and billing management.
  • Free signup credits — new accounts receive a configurable number of free credits.
  • Light & dark themes and full multi-language support including RTL layouts.

Server Requirements

The install wizard verifies every requirement automatically in its first step, so a misconfigured server is caught before anything is written.

RequirementMinimumNotes
Node.js 18.x or newer Checked by the wizard. LTS releases recommended.
MySQL 5.7+ / 8.0+ Reachable from the app server; default port 3306. The wizard can create the database if it doesn't exist.
Writable directories project root, public/storage The root stores env files written during install; public/storage holds generated images (auto-created if missing).
Dependencies npm install completed Including dev dependencies — the wizard runs the Prisma CLI from node_modules to create the schema.
sharp loads on the host platform Installed with dependencies; on platform mismatch, reinstall on the server (see Troubleshooting).
Memory 1 GB+ recommended Image processing with sharp benefits from headroom.
ℹ️

External services you'll want ready: at least one AI provider API key (Google AI Studio or OpenAI), SMTP credentials for transactional email, and a Stripe account if you plan to sell credit plans. All three are configured later in the admin panel — none are needed to install.

Quick Start

From a fresh server to a running platform:

  1. Copy the server folder Place the Admin and Web Install V1.0 folder into your web directory and work inside it — that folder is the server.
  2. Set your domain Open .env.production and set NEXT_PUBLIC_APP_URL to the URL the app will be served from. Don't add a DATABASE_URL line — it's absent from the template by design — and leave AUTH_SECRET empty; both are filled automatically.
  3. Install & build 
npm install
npm run build
  1. Start the server 
# direct
npm run start

# or with PM2 (recommended for production)
pm2 start ecosystem.config.js
pm2 startup   # once per server: boot PM2 with the OS (run the sudo command it prints)
pm2 save      # snapshot the process list so it's resurrected after a reboot
  1. Open your domain Every URL redirects to /install. Walk through the wizard, then sign in at /admin/login with the super admin account you created.
⚠️

Set NEXT_PUBLIC_APP_URL before building. Values prefixed NEXT_PUBLIC_ are embedded into the compiled output at build time. If you change your domain later, update the value and run npm run build again — otherwise email links and payment redirects will keep pointing at the old URL.

Installation Process

Installation is enforced by middleware: until the wizard completes, all pages redirect to /install and API routes answer 503. Once finished, the wizard seals itself permanently — visiting /install on an installed copy redirects home.

Before you build

The shipped env templates contain only a handful of keys. Two of them matter before the build:

# --- App ---
NEXT_PUBLIC_APP_NAME="6amStudio"
NEXT_PUBLIC_APP_VERSION="1.0"
# Hosted URL — set before `npm run build` (used in email links & payment redirects).
NEXT_PUBLIC_APP_URL="https://images.example.com"
# Optional CDN/storage origin for uploaded files — empty = NEXT_PUBLIC_APP_URL.
NEXT_PUBLIC_STORAGE_URL=

# --- Managed automatically by the installer — do not set DATABASE_URL by hand ---
# The wizard's database step writes DATABASE_URL here. Leave it ABSENT, not
# blank: a blank value is loaded into the process at boot and shadows the value
# the installer writes, so the app can't reach the database afterwards.
# AUTH_SECRET is generated on first boot if empty.
AUTH_SECRET=
  • DATABASE_URL is not in the template at all — leave it out. The wizard's database step writes it into every env file present, atomically. Don't add a blank DATABASE_URL= line yourself: an empty value is loaded at boot and shadows the one the installer writes, leaving the app unable to reach the database.
  • AUTH_SECRET (the session-signing key) is generated uniquely for your deployment at first server boot. No two installations share a key. If you prefer to supply your own, set any value and it will be respected.

The install wizard, step by step

  1. Server requirements The wizard checks the Node.js version, directory permissions, the Prisma CLI, and the sharp image library. Every check must pass before you can continue; each failing row explains how to fix it.
  2. Database Enter MySQL host, port, database name, username, and password. The wizard tests the connection, creates the database if it doesn't exist, builds the schema, and seeds system data (settings, effects, prompts, mail templates, the Stripe gateway record). It then writes DATABASE_URL into your env files and switches the running process over — no restart needed mid-wizard.
  3. License activation Enter your marketplace username and purchase code. The license server verifies the code for your domain. Installs on localhost skip this check, so you can evaluate on a development machine without consuming an activation.
  4. Super admin Create the first administrator (name, email, password of at least 8 characters). This finalizes the installation and unlocks the application.
🛑

Existing data is never erased silently. If the target database already contains tables, the wizard stops with a warning showing the table count, and you choose: erase everything in that database, or go back and point at a different one. The wipe only happens after your explicit confirmation.

After installation

  • The wizard hands you a link to /admin/login — sign in with the super admin account from step 4.
  • The only account in the system is that super admin. End users register themselves; there are no demo accounts to delete.
  • Head to Admin Configuration to connect AI models, SMTP, and payments — the platform is installed, but it can't generate images or send email until keys are added.

Environment Reference

6amStudio deliberately keeps the env surface tiny — nearly all configuration lives in the database and is edited from the admin panel. The same keys exist in .env.development (used by npm run dev) and .env.production (used by npm run build / npm run start).

KeyWho sets itPurpose
NEXT_PUBLIC_APP_URL You, before building The public URL of the deployment. Used in email links, payment redirects, and the OAuth redirect-URL display. Baked in at build time.
NEXT_PUBLIC_STORAGE_URL You (optional) A CDN or separate origin for serving uploaded files. Leave empty to serve them from NEXT_PUBLIC_APP_URL.
NEXT_PUBLIC_APP_NAME / NEXT_PUBLIC_APP_VERSION Pre-set Display name and version string.
NEXT_PUBLIC_IS_DEVELOPMENT_MODE Pre-set true in development only — exposes the interactive API docs at /api-docs.
DATABASE_URL Install wizard MySQL connection string. Written automatically during the wizard's database step. Not present in the shipped template — leave it out entirely (absent, not blank) in a fresh copy.
AUTH_SECRET First server boot Session-signing key, generated uniquely per deployment. Leave empty; set a value only if you want to supply your own.
🔑

Where are the API keys? AI provider keys, SMTP credentials, payment gateway keys, OAuth client secrets, and Firebase config are all stored in the database and managed from the admin panel — they never live in env files, so updating them never requires a rebuild or restart.

Admin Configuration

After installing, work through these sections in the admin panel. The platform is usable the moment AI models are connected; the rest can follow at your pace.

AI Models required

Admin → AI Models

  • Add one entry per model you want to offer. Choose the provider (Google or OpenAI), pick the model, and paste the provider API key.
  • Get keys from Google AI Studio (Gemini image models) or the OpenAI platform (GPT Image / DALL·E).
  • Set a credit cost per model — this is how many credits one generation deducts from the user. Expensive models can simply cost more credits.
  • Mark one model as the default; users can switch models in the editor.
  • Stored keys are masked in the UI after saving. Deactivate a model to remove it from the editor without deleting it.

SMTP & Mail Templates

Admin → SMTP and Admin → Mail Templates

  • Enter your mail server's host, port, username, password, and from-address, then use the test send to verify delivery.
  • SMTP powers password-reset codes, welcome emails, and purchase receipts. Without it, users cannot complete the forgot-password flow.
  • Every outgoing email is built from an editable HTML template. Templates support placeholders like {{brand_name}}, {{user_name}}, and {{app_url}}, replaced at send time, and each template can be previewed before saving.

Payment Gateways

Admin → Third-party → Payment

  • Stripe ships ready to configure: enter the secret API key, choose live or test mode, and optionally set a display title and logo for the checkout button.
  • Checkout flow: the user picks a plan → is redirected to the gateway's hosted checkout → returns to the app where the session is verified server-side before credits are granted. Webhooks are received at /api/billing/webhook/<gateway>.
  • The gateway layer uses a registry pattern, so additional processors can be integrated by a developer without touching the billing core.
  • Only gateways marked active appear to users. Plans themselves are managed under Admin → Plans.

Google OAuth (social login)

Admin → Third-party → OAuth

  1. Create an OAuth client in the Google Cloud Console (type: Web application).
  2. Register the redirect URI shown on the admin OAuth page (it is derived from your NEXT_PUBLIC_APP_URL).
  3. Paste the Client ID and Client Secret into the form and enable the provider.

A "Continue with Google" button then appears on the login and registration pages. Accounts are matched by email — an existing user signing in with Google is linked automatically.

Firebase (push notifications, optional)

Admin → Third-party → Firebase

  • Entirely optional — skip it and the in-app notification center still works; you only lose browser push delivery.
  • Server side: paste the service-account values (project ID, client email, private key) from a Firebase service-account JSON.
  • Client side: paste the web-app config values (API key, sender ID, app ID, …) and the VAPID public key for web push.

Branding & Business

Admin → Branding and Admin → Business

  • Branding: app name, slogan, logo, favicon, and the primary theme color for dark and light modes. Changes apply live across the whole product — login screens, editor, emails — with no rebuild.
  • Business: whether new signups receive free credits, and how many.

General & Storage

Admin → Settings

  • Locale defaults — country, timezone, and the currency used on plan and billing pages.
  • Storage driver — generated images are stored on the local filesystem under public/storage by default and served from /storage/…. An S3-compatible driver is available for object storage / CDN setups; configure bucket, region, keys, and an optional public URL in the same section.

Localization

  • Admin → Languages manages the language list: ISO code, display name, native name, text direction, default flag, and active state.
  • Right-to-left languages are fully supported — setting a language's direction to rtl flips the entire UI, including the editor.
  • Users pick their language in the app; the choice is remembered per browser. Visitors without a choice get the default language.
  • UI strings are served per language as message bundles, so adding a language does not require a rebuild.

Mobile App

Alongside the web platform, 6amStudio ships a companion Flutter mobile app for Android and iOS. The app talks to the same backend you installed above through the REST API — point its base URL at your domain and it serves the AI editor, projects, gallery, billing, and push notifications natively on mobile.

The steps below cover personalising and shipping the app under your own brand. Files are referenced relative to the Flutter project root; commands assume the Flutter SDK and Android Studio / Xcode are installed.

ℹ️

Order matters. Work through Mandatory Setup top to bottom — in particular, change the package / bundle identifier before setting up Firebase, since Firebase configuration is tied to that identifier.

1 · Mandatory Setup

1.1 Change App Name required

Set the display name in all three platforms:

// 1. lib/util/app_constants.dart
static const String appName = 'YOUR_APP_NAME';
<!-- 2. android/app/src/main/AndroidManifest.xml — update the label -->
<application android:label="YOUR_APP_NAME" ... >
<!-- 3. ios/Runner/Info.plist — update CFBundleName & CFBundleDisplayName -->
<key>CFBundleDisplayName</key><string>YOUR_APP_NAME</string>
<key>CFBundleName</key><string>YOUR_APP_NAME</string>

1.2 Change App Icon

Generate launcher icons from a single source image using appicon.co, then drop the generated assets into the native projects:

  • Android — replace the generated mipmap-* folders into android/app/src/main/res/.
  • iOS — replace the generated Assets.xcassets (the AppIcon set) into ios/Runner/.

1.3 Change Base URL required

Install and host your 6amStudio server first (see Installation Process), then point the app at it. Open lib/util/app_constants.dart and set baseUrl to your domain: 

// lib/util/app_constants.dart
static const String baseUrl = 'https://your_domain.com';
⚠️

No trailing slash. Do not put a / at the end of the base URL. This should match the NEXT_PUBLIC_APP_URL of your server install.

1.4 Change App Package / applicationId required

Give the app its own unique identifier across both platforms.

  1. Find the current package name Locate the existing applicationId in android/app/build.gradle.kts.
  2. Replace it everywhere (Android Studio) Right-click the project folder → Replace in Files (Ctrl + Shift + R on Windows/Linux, ⌘ + Shift + R on macOS). Enter the existing package name in the first box, your new package name in the second, then Replace All.
  3. Match the iOS Bundle Identifier Open ios/Runner.xcworkspace in Xcode → Runner target → Signing & Capabilities → set Bundle Identifier to the same value.
🛑

Change the package name before setting up Firebase — Firebase registration below binds your google-services.json / GoogleService-Info.plist to this identifier.

1.5 Setup Firebase for Push Notifications

Prerequisite: change the package name first (1.4), then create a project in the Firebase Console.

Android
  • Add an Android app to the Firebase project using your package name.
  • Download google-services.json and replace the existing file at android/app/google-services.json.
  • Create a white PNG notification icon and place it at android/app/src/main/res/drawable/notification_icon.png.
iOS
  • Add an iOS app to the same Firebase project using your Bundle Identifier.
  • Download GoogleService-Info.plist and add it to ios/Runner/ through Xcode so it is included in the Runner target.
  • For full iOS configuration, follow the firebase.flutter.dev documentation.
⚠️

Test push on a real device. Do not test push notifications on an emulator or simulator.

2 · Customisation

2.1 Language

Add a new language

  1. Create the translation file In assets/language/ add a file named after the language code — e.g. es.json for Spanish. Copy everything from en.json into it, then translate only the text after each colon — never change the keys.
  2. Register the language In lib/util/app_constants.dart, add a LanguageModel to the languages list: 
// lib/util/app_constants.dart
LanguageModel(
  languageName: 'Spanish',
  countryCode: 'ES',
  languageCode: 'es',
),

Then uninstall and reinstall the app to pick up the new bundle.

  • Remove a language — delete its LanguageModel from the languages list.
  • Set the default — move the desired LanguageModel to the first position in the list.

2.2 Change App Color

  • Open lib/core/theme/app_colors.dart and adjust the brand colors and gradient (gradientStart, gradientEnd, and the other accent colors).
  • Open lib/core/theme/app_theme.dart and update the light theme colors (primary, background, surface, text).
  • In the same file, repeat for the dark theme colors.

2.3 Change App Font

  1. Add the font files Download a font (e.g. from Google Fonts), unzip it, and copy the .ttf files into assets/font/.
  2. Declare it in pubspec.yaml Under the flutter: section, add a fonts: entry with a family name and one asset + weight per style (indentation matters in YAML): 
# pubspec.yaml
flutter:
  fonts:
    - family: YourFontFamily
      fonts:
        - asset: assets/font/YourFont-Regular.ttf
          weight: 400
        - asset: assets/font/YourFont-Bold.ttf
          weight: 700
  1. Reference the family in code Update fontFamily in lib/core/theme/app_theme.dart and lib/util/styles.dart. The family value in pubspec.yaml and fontFamily in code must match exactly, or the font won't load.
  2. Bundle it Run flutter pub get so the new font is packaged into the app.

2.4 Change Notification Sound

Android: replace android/app/src/main/res/raw/notification.mp3 with your desired sound, keeping the filename notification.mp3.

3 · Google Login (3rd-party)

Firebase project setup

In the Firebase Console, open the project you created for push notifications, then go to Authentication → Sign-in method → Add new provider → Google, enable it, and Save.

Android configuration
  • In Project Settings → Android apps, select your user app and add the SHA-1 and SHA-256 fingerprints (command below).
  • After launch, also add the SHA keys from Google Play Console → App Integrity.
  • Download the updated google-services.json and place it in android/app/.
# get the SHA keys from the debug keystore
keytool -list -v -keystore ~/.android/debug.keystore \
  -alias androiddebugkey -storepass android -keypass android
iOS configuration
  • Get the Client ID from cloud.google.com → APIs & Services → Credentials → OAuth 2.0 Client IDs.
  • Edit ios/Runner/Info.plist and add the Client ID (GIDClientID) and its reversed value under CFBundleURLSchemes:
<!-- ios/Runner/Info.plist -->
<key>GIDClientID</key>
<string>YOUR_IOS_CLIENT_ID.apps.googleusercontent.com</string>
<key>CFBundleURLTypes</key>
<array>
  <dict>
    <key>CFBundleURLSchemes</key>
    <array>
      <string>com.googleusercontent.apps.YOUR_IOS_CLIENT_ID</string>
    </array>
  </dict>
</array>

4 · Build & Release

Android

Build a release APK:

flutter build apk

The APK is generated in build/app/outputs/flutter-apk/ as app-release.apk. To produce smaller per-architecture APKs: 

flutter build apk --split-per-abi \
  --target-platform android-arm,android-arm64,android-x64

See Flutter's Android deployment guide for details.

⚠️

Configure release signing before publishing. By default the release build is signed with the debug key (see the release block in android/app/build.gradle.kts). A debug-signed build runs locally but cannot be uploaded to Google Play. Set up your own keystore + key.properties before a production release.

iOS

Apple does not allow side-loading release builds — deploy through TestFlight or the App Store. Follow Flutter's iOS deployment guide for complete instructions.

🔒

Keep secrets out of version control. Replace all placeholder values with your own before publishing, and never commit google-services.json, GoogleService-Info.plist, key.properties, or keystore files.

Deployment

Run modes

# development (loads .env.development, dev server with hot reload)
npm run dev

# production (loads .env.production)
npm run build
npm run start     # serves on port 3000

PM2 (recommended)

An ecosystem file ships in the project root, pre-configured for a single fork-mode instance on port 3000 with log files and a memory-restart guard:

pm2 start ecosystem.config.js
pm2 startup             # once per server: registers PM2 as a system service
pm2 save                # snapshot the process list for auto-resurrection on boot
pm2 logs 6amstudio       # tail application logs
pm2 restart 6amstudio    # after updates or env changes

pm2 startup prints a sudo command — run it once and PM2 will start with the operating system. pm2 save records what PM2 should bring back; re-run it whenever you change the process list, or the next reboot restores the old one.

⚠️

Run the install wizard on a single instance. Keep instances: 1 (as shipped) at least until installation completes — the wizard writes env values into the running process. If you later scale with PM2 cluster mode, do a full pm2 restart after installing so every worker boots from the finalized env files.

Reverse proxy

Point your web server at the Node process. A minimal Nginx site:

server {
    listen 80;
    server_name images.example.com;

    client_max_body_size 20M;   # uploads up to the app's 15 MB limit

    location / {
        proxy_pass         http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_set_header   Upgrade $http_upgrade;
        proxy_set_header   Connection "upgrade";
    }
}

Then add TLS (e.g. certbot --nginx). Remember: if the final public URL differs from what you built with, update NEXT_PUBLIC_APP_URL and rebuild.

File storage notes

  • Generated images live in public/storage — include this directory in your backup strategy alongside the database.
  • The app already sends permissive CORS headers for /storage/* so the editor canvas can composite stored images; no proxy configuration is needed for this.
  • Upload/server-action payloads are capped at 15 MB by the application.

REST API

Every user-facing feature is backed by a versioned REST API under /api/v1, authenticated with Bearer JWT tokens obtained from the login/register endpoints.

📜

Interactive documentation: run the app in development mode (NEXT_PUBLIC_IS_DEVELOPMENT_MODE=true) and open /api-docs for a browsable OpenAPI reference of every endpoint, parameter, and response shape. The docs page is disabled in production builds by default.

GroupBase pathCovers
Auth /api/v1/auth/* Register, login, social login, forgot/reset password with OTP verification
User /api/v1/user/* Profile, avatar, activity, analytics, push-token registration
Projects /api/v1/projects/* CRUD, thumbnails, and the edit tree
Editor /api/v1/editor/* Effect presets and prompt/template suggestions
Templates /api/v1/templates/* Template gallery, categories, usage tracking
Billing /api/v1/billing/* Plans, gateways, checkout, payment status, history
Notifications /api/v1/notifications/* List, mark read, bulk mark read
Config /api/v1/config, /api/v1/ai/providers Public app config, branding, and active AI models

Conventions

  • Authenticated requests send Authorization: Bearer <token>.
  • List endpoints are paginated and return data, total, page, and totalPages.
  • Errors return an appropriate HTTP status with a JSON body of the form { "error": "…" }.

Troubleshooting

Requirements step: "Prisma CLI not found"

Dependencies were installed without dev packages. Re-run on the server:

npm install --include=dev

Requirements step: sharp fails to load

The sharp binary was built for a different platform (common when node_modules was copied from another OS). Rebuild it on the server:

npm rebuild sharp
# or, if that fails:
rm -rf node_modules && npm install

Database step: connection refused / access denied

  • Verify the MySQL host is reachable from the app server (firewall, bind-address).
  • Confirm the user has privileges on the target database — and CREATE rights if the wizard should create it.
  • Special characters in passwords are handled automatically by the wizard; no manual URL-encoding needed.

"Database already contains N tables" warning

The wizard found existing data in the database you pointed it at. Choose another database if that data matters, or confirm the erase option to wipe it and install fresh. Nothing is deleted without explicit confirmation.

Email links point to localhost

NEXT_PUBLIC_APP_URL was not set (or was localhost) when the app was built. Set it to your real domain in .env.production, then rebuild and restart: 

npm run build && pm2 restart 6amstudio

License activation fails

  • Check the marketplace username and purchase code for typos (copy-paste both).
  • A purchase code is bound to a domain — if you're moving servers or domains, follow the activation-issue link shown in the wizard to resolve it.
  • localhost installs never need activation.

Image generation fails in the editor

  • Confirm at least one AI model is configured and active under Admin → AI Models.
  • Verify the provider API key is valid and the provider account has quota/billing enabled.
  • Check the user has enough credits for the selected model's cost.

Port 3000 already in use

# find and stop the occupant…
lsof -i :3000
# …or change the port in ecosystem.config.js (args + PORT) and your proxy

Re-running the installer (development only)

Installation is one-way by design. To reset a development machine:

-- in MySQL
DELETE FROM installations;

…then restart the server — the installed state is cached in-process and only re-read on boot.

Customization

No-code (admin panel)

  • Rebrand entirely from Admin → Branding: name, slogan, logo, favicon, and theme colors for both dark and light modes — applied live.
  • Curate the creative library: effects, templates, template categories, and suggested prompts are all data, managed in the admin panel.
  • Shape the economy: plans, per-model credit costs, and free signup credits define your pricing without code.
  • Rewrite every email in the mail-template editor.

For developers

  • Theme source — src/config/theme.ts holds the full dark/light palettes as plain hex values; every tint and opacity variant is derived automatically.
  • Payment gateways — implement the gateway interface and register it alongside Stripe; checkout, webhooks, and crediting are handled by the shared billing core.
  • AI providers — models are wired through the Vercel AI SDK, so adding further providers follows the existing Google/OpenAI pattern.
  • Database — the Prisma schema lives in prisma/schema/; after changes run prisma db push and regenerate the client.
  • The codebase is fully typed TypeScript with App Router conventions — API routes under src/app/api, feature logic under src/features, shared libraries under src/lib.
